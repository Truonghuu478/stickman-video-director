# Video clip QC

Review the current clips against the episode's own instructions and prepare a concise, actionable handoff. The user performs the fixes. This workflow does not regenerate clips, upload files, edit source clips, change the edit plan or timeline, or render a final video; only create the review folder and its contents. Follow a later explicit user instruction if the user changes that scope.

1. Find the episode root and read its `FLOW.md` or equivalent brief, shot list, QC rules, and existing cut plan if present. Treat project-specific details as requirements for that project, not universal rules. Inventory the expected and actual files in `clips/`; report missing, extra, unreadable, or ambiguous clips. Never fabricate an expected shot list when no brief is available.
2. Create a new, uniquely named folder for this review under `<episode>/qc-revisions/`, such as `2026-11-22-001`; never overwrite a previous review. Save `REPORT.md` there even if clips are missing, all inspected clips appear acceptable, or a tool is unavailable. Put only useful evidence such as annotated or timestamped extracted frames in this folder; preserve prior clips and reports.
3. If the episode has `shots.tsv`, run `python3 <repo>/skills/dao-dien-tap/scripts/check_plan.py <episode>/shots.tsv --clips` and include its ERROR/WARN lines; check that every `turn=yes` segment really shows the choice inside its kept range. Use `ffprobe` for each available clip to inspect actual video duration, dimensions, frame rate, and audio stream. Check cut in/out points against actual clip duration and whether the planned edit includes the decisive action. Check the planned total against any stated target. Suggest concrete timing changes, but do not apply them.
4. Inspect the actual video using an available video-viewing tool. If only still images are available, extract timestamped frames across the whole clip and more densely around critical actions, mouths, hands, cuts and transitions; inspect them visually. Compare identity, props, colours, lighting, continuity, movement, watermark/text and the ending with the brief where applicable. Check the intended cut range as well as the source when relevant. Identify which observations come from sampled frames; they cannot prove every frame is correct or that motion is smooth. Save representative evidence for actionable issues.
5. Evaluate audio by actual listening only when the environment supports it. Stream metadata and `ffmpeg` volumedetect can show whether audio exists and its level, but cannot establish intelligibility, silence, dialogue, ambience, effects, clipping perception, or sync. Mark unlistened audio and other unverified checks as **Unverified**, not Pass. Include useful levels if measured and flag suspicious peaks for human audition without calling them proof of clipping.
6. Write `REPORT.md` in the user's language unless requested otherwise. Begin with overall **Pass / Needs fixes / Incomplete** and the inspection limits. Include a compact status for every expected clip, actual duration and sound availability; separate verified failures from suspicions and unverified items. For each issue give the clip, timestamp or range, observed evidence, intended result from the brief, and a precise action the user can take. For regeneration, include an adapted ready-to-use motion prompt if the original prompt exists, preserving its intended action and constraints; clearly label it as a suggestion. For timing-only issues propose in/out points and their impact on total runtime. Reference saved evidence with relative links. End with a short user checklist for fixes and rechecking. If a final video exists, inspect it only when requested; otherwise state that it was not assessed.

Report the new folder location and the main blockers. Do not assert complete visual, audio, or final-video QC when the available evidence cannot support it. The next review creates a separate folder, leaving this review intact.
