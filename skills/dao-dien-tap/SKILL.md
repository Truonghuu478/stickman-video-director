# Direct one episode

Each `$dao-dien-tap` invocation creates **one standalone episode**, with a specific final duration of **20–30 seconds** unless the user specifies otherwise, in vertical 9:16. Use any topic, duration or image supplied by the user. When invoked without arguments, make the creative choices and deliver the complete package in the same turn. By default, write the story, acting and location sound direction, editing instructions, post copy, image prompts and motion prompts in English. Honor a user-specified output language. The conversation language follows the user's instructions.

## Use the repository core

Resolve this skill's actual directory through symlinks, then read [directing-stickman-videos](../directing-stickman-videos/SKILL.md) and [mode execution boundaries](../directing-stickman-videos/references/mode-execution-boundaries.md). Use **A · Director** with the **A6 Amber Noir** style by default (the style behind the README's accepted samples); another style only when the user names it. Read [amber-noir](../directing-stickman-videos/references/amber-noir.md) and [a6-reference-prompts](../directing-stickman-videos/references/a6-reference-prompts.md) before writing any prompt, and apply them over the generic A1–A5 contract where they differ. Read and apply these references at the appropriate step:

- For the storyboard, use [storyboard-template](../directing-stickman-videos/references/storyboard-template.md) for each scene's purpose, rhythm, composition and transition state. Use “Separate design, position and state” in [cozy-storytelling](../directing-stickman-videos/references/cozy-storytelling.md) to track characters and props.
- For prompts, use [a6-reference-prompts](../directing-stickman-videos/references/a6-reference-prompts.md): each Start-frame prompt is fully expanded (style, cast, world, composition, constraints; no placeholders), and each Motion prompt is short. [omni-flash-prompt-contract](../directing-stickman-videos/references/omni-flash-prompt-contract.md) is the A1–A5 contract and is not the A6 standard.

Complete the storyboard and prompts in one turn unless the user asks to review the storyboard first. Build the story around visible action that reads with the sound off. Each source clip is up to 8 seconds (Veo 3.1 Fast, the model behind the accepted A6 sample; check the live Flow model list and durations). Preserve the appearance in a supplied reference image and change location when the story calls for it.

**Characters are silent.** The accepted A6 samples use non-speaking actors; the A6 docs record that Flow did not keep character mouths stable and that offscreen-narrator wording did not reliably stop speaking. Flow supplies only ambience and effects timed to visible sources. Write no dialogue lines, voice profiles or narration, and request "No dialogue or narration" in every Motion prompt. Tell the story through visible action, props and reactions. If the user explicitly asks for spoken dialogue in an episode, state the risk (mouth sync, voice drift between clips) and then use the native-speech guidance in [voice-continuity](../directing-stickman-videos/references/voice-continuity.md). Narration, TTS and music are out of scope unless asked.

## Choose and direct the story

0. **Research trends** for an empty invocation:
   - **Gather:** Use available search and web-fetch tools, such as 9router-web-search and 9router-web-fetch, to retrieve the most-viewed videos of the past 24 hours at https://endless.app/radar/tiktok/vietnam (the page lists about 20, plus top sounds and hashtags; `fetch-combo` returned it as markdown). Search roundups with `search-combo` and `time_range: week`. Find and read 2–3 Vietnamese social-media trend roundups published in the past seven days from sources such as Tuổi Trẻ, VTV or Advertising Vietnam. List holidays in the next 14 days. Use TikTok Creative Center links or screenshots supplied by the user; that page returns empty results to crawlers.
   - **Filter:** Keep trends with a behavioral core that can be acted physically. Borrow the situation, not music, footage or script. Exclude trends dependent on copyrighted music, lyrics, lip-sync, a real person's appearance or dance, celebrities or KOLs, on-screen text, advertising or sponsorship. Exclude sensitive news such as accidents, poisoning, violence or personal scandals, mockery of appearance or groups, and copies of a specific video.
   - **Analyze:** For each remaining trend, record the emotional core, original situation and repeated behavior, sharing mechanism, element adapted to the film, and estimated expiry. Favor rising trends or relevant holidays, and drop trends that peaked over a week ago. Choose a publication date before expiry with 1–3 days for production.
   - **Fallback:** When sources are missing or filtered trends suggest only a situation without a good story, record why in TRENDS.md. Choose an everyday observation from step 2 and state that there is no source trend.
1. Store episodes at `../stickman-video-projects/doi-thuong/` relative to the repository root. Before selecting a story, read the **Episode signature** or legacy **Dấu tập** line in each `*/FLOW.md`. It records *setting | what the character wants | obstacle | ending*. If both the conflict and ending match an earlier episode, choose another story. Any area of daily life may supply a topic. A character may return, but new viewers must understand each episode independently. Create a new dated, short-named directory, choosing another suffix if it exists. When the user supplies clips or asks to continue editing, reopen the named episode or the one active in the conversation.
2. The default audience is **Vietnamese young people aged 16–28** scrolling TikTok/Reels. Choose a moment they encounter weekly and recognize through a **specific behavior**. Possible areas include roommates and rented rooms, deadlines and procrastination, group chats and read receipts, crushes, Monday work, sales and end-of-month finances, food delivery, low phone battery, close friends, parents and relatives, and pets taking over the home. These are suggestions, not a closed list. Avoid stories only older viewers would recognize.

   Sketch **three ideas with different things to say**. For each, write an observable behavior, why the character does it, and an ending image that might linger. A meal could express pride, familiarity or mischief. Choose an idea through which viewers can recognize a particular person by their actions. Trend heat helps determine publication timing.

   **Before dividing into shots**, write the film from beginning to end using actions. Open when something worth watching is already happening. Let an event force a character to choose, then show the consequence or another person's reaction. In comedy, give the viewer enough evidence to expect one thing, then let the character do another. In an emotional story, find a gesture that says what the character hesitates to say. Keep a quiet beat when it lets the viewer understand.

   **Review the story visually.** Remove the title, caption, sound and psychological explanations. Identify (a) which image makes you want to see what happens next, (b) which moment reveals something about the character, and (c) which detail you would recount to a friend. If the answer is only “relatable”, “moving” or a generic lesson, rewrite the decisive action or try another idea before making images. Record this as editorial judgment; claim audience reactions only after real viewers have watched.
3. Lock appearance from a reference image if provided. Otherwise design a new A6 cast for the story: one solid matte-black round head with two small cream-white oval eyes and one short cream line mouth, no hair, no skin, simple black mitten hands, slim black neck and limbs, plus story-specific clothing and props. The bundled sample's hoodie is style only, not this story's cast. Repeat the full English appearance description verbatim in every Start-frame prompt containing that character. Expression, pose, situational clothing and props may change when motivated by the story. Use the user's cast if specified.
4. For every shot, decide what the audience must see before choosing the shot size. A wide shot establishes positions, a medium shot shows a decision through hands, shoulders or feet, and a close-up shows evidence or consequence. Each clip contains one main action and enough reaction. Describe playable physical movement rather than emotion labels. Maintain the camera axis and eyelines within a space. Change angle only when it reveals something or follows the action.
5. After the ending is chosen, select a natural reason to interact for the post. For example, identify the person a viewer might send the film to, or a choice two people could interpret differently. Keep background details when they reveal a habit or relationship or prepare a discovery. When the final beat already evokes the story, let that image end the film.

## Deliverables for each invocation

Write **TRENDS.md** in the episode directory with the research date, source links, raw trends, rejected trends and reasons, the five-field analysis, three ideas and the detail that makes the chosen idea worth filming.

Write **FLOW.md** in the episode directory. Begin with the title, **Episode signature**, and a **Source trend** line immediately below it with the trend name, source link and expected expiry. Follow with a summary and a beginning–middle–end script with visible action. For a fallback story, state no source trend and record sources and expiry status. Then record appearance locks, spatial relationships, and props to track. Give every shot an S01, S02… code and everything needed to render it independently:

- Choose cuts when viewers have just enough information. Compare the final shot's kept range with the actual timing of the decisive gesture and reaction. Work backward from the final edit at 24 fps. For each shot record the requested Flow duration, expected retained source range, and entry/exit times in the film. Veo 3.1 Fast in Flow returned **8 s** clips (8.04 s measured); plan each retained range inside about 0.5–7.5 s, and split an action that needs more. If the live interface offers other durations, record what was used. Planned in/out points are estimates: in the first test the foot was still retracting at the planned out point, so set final cuts from the real frames. A scene can use multiple images and shots: split into a wide establishing shot, contact close-up and reaction when viewers need all three. Each split gets its own shot code, start image and prompt. A retained segment may be shorter than four seconds. Do not fix the number of shots.
- Record shot size, camera position, eyelines, and opening state → action/contact → final state. At each cut, name the action or gaze leading to the next shot and one detail to match, such as hand, direction, prop or position. Make any time or location jump visually clear.
- Supply one complete **Start frame** image prompt and one complete **Motion** prompt in separate copyable blocks. The Start frame shows the instant before the action and keeps the ending hidden; it is fully expanded (style, cast, world, composition, constraints) and never uses placeholders. Keep decisive details visible in the vertical frame and away from the right edge and bottom where TikTok's interface covers the picture (approximate). No generated subtitles, speech bubbles or readable text; phones and notes show abstract scribbles. Make each prompt standalone.
- Each **Motion prompt** has a short action part (2–4 sentences) followed by the fixed anatomy lock and sound tail below. The action part describes ONE action, ONE reaction and ONE motivated camera move (locked, or a slow push with a stopping point). State the end state simply and early. Repeat the visible appearance and setting in a sentence. Leave room before and after the action for trimming. Do not paste a character sheet or a long timed script. Lessons from tested clips: vague changes ("the shadow grows") and big camera tilts failed, and an end state buried in a long sentence was ignored.
- Every Motion prompt carries this **anatomy lock** verbatim, because Veo adds eyebrows, eyelids and fingers once a character emotes or reaches:
  > Keep the drawing exactly as the first frame: the face is only two cream oval eyes and one short line mouth, with no eyebrows, eyelids, nose or teeth; hands stay solid black mitten shapes with no fingers or thumbs; feet stay plain black shapes with no toes.
  Avoid asking for an action that needs a hand the start frame does not show (reaching for a phone, pulling a blanket from under it); Veo then invents a realistic hand. Show the change through body, eyes or the prop moving instead, or start the frame with the mitten already on the prop.
  Repeat in the Motion prompt any state that must not change during the clip ("the lamp stays off"); in the first test a lamp that was off only in the start frame came on in the clip.
- Every shot is **wordless**: the character does not speak and the mouth stays a small closed line. End each Motion prompt with: quiet location ambience and one or two effects timed to the visible source; "No dialogue, narration, music, text or captions."
- Example Motion prompt for a six-second shot:
  > Locked medium shot at a rainy bus stop, matching the first frame exactly. The silent stickman in the mustard raincoat looks up the empty road, then slowly lowers onto the bench and hugs the closed umbrella. Keep the drawing exactly as the first frame: the face is only two cream oval eyes and one short line mouth, with no eyebrows, eyelids, nose or teeth; hands stay solid black mitten shapes with no fingers or thumbs; feet stay plain black shapes with no toes. Soft rain and distant traffic; one small bench creak as they sit. The mouth stays a small closed line. No dialogue, narration, music, text or captions.
- End FLOW.md with assembly order, image and clip names, and sound cues per shot. Then use [dang-bai-tiktok-reels](../dang-bai-tiktok-reels/SKILL.md) to write the episode's POST.md.

Write **cut.tsv** with tab-separated columns `clip`, `flow_s`, `in_s`, `out_s`. Each row is a retained segment in assembly order, with a clip path relative to the episode directory. Choose the total duration, then run `python3 <skill>/scripts/cut.py <episode>/cut.tsv --target <final-seconds> --remotion > <episode>/timeline.json`. Deliver this timeline with a copy of [episode.jsx](assets/episode.jsx) for each episode. Remotion reads each segment's in point and duration at 24 fps from JSON; its film position is the sum of previous durations. Regenerate JSON after any cut.tsv adjustment.

## Generate and check start images before Flow

For every new episode, follow the image generation steps in [stickman-flow-pipeline](../stickman-flow-pipeline/SKILL.md). The default shooting package has **one 720×1280 PNG per shot code**. Skip only if the user specifically requests just a storyboard or prompts.

1. Create `flow-input/` and `qc/` in the episode directory. Use [9router-image](/Users/truongle/.9router/.agents/skills/9router-image/SKILL.md) to inspect image models and capabilities. `gen-frame.sh` attaches the bundled A6 style image to every call. Generate the **anchor shot** first: the shot that shows every recurring character clearly and full body (in the first test S05, because S01 was a lump under a blanket). `bash "$generator" "$shot_prompt" "$episode/flow-input/$anchor.png"`, where `generator` is the script's actual path. Redo until the cast passes, then pass it as the cast reference for every other shot, which may run in parallel: `bash "$generator" --ref "$episode/flow-input/$anchor.png" "$shot_prompt" "$episode/flow-input/$shot_id.png"`. The reference also leaks its lighting and prop states (the anchor's lit lamp turned up in a shot that needed it off), so state every prop state that differs from the anchor explicitly in that shot's prompt. Each prompt still repeats the full cast description, but only the new pose, setting and action need detail. Reference-guided generation requires an `edit`+`multiImage` model. The default model is `cx/gpt-image-2`; set `NINEROUTER_IMAGE_MODEL` when the user selects another model, or follow the 9Router skill for provider-specific features. Save 720×1280 PNGs and recheck framing after cropping. If the skill or selected model is unavailable, report it rather than silently changing provider. If the user has an image with the correct composition and opening state, save and reuse the corresponding portrait PNG; other shots still need their own images.
2. Confirm each PNG's dimensions with ffprobe. Use FFmpeg to assemble the images in shot order into `qc/contact-sheet.jpg` and inspect faces, hands, clothing, props, eyelines and pre-action positions. Correct prompts and regenerate incorrect images. When resuming an interrupted episode, preserve images that already pass and handle missing or failed shots.
3. Place actual image paths beside Motion prompts in FLOW.md and deliver the image directory and contact sheet. Compare shot codes with inspected PNGs. If the service fails or quota is exhausted, record the cause and missing shot codes so work can resume; call the package ready only when all images pass.

## From shooting package to MP4

- In Google Flow, choose **Veo 3.1 Fast** (the model behind the accepted A6 sample) if the live model list offers it, with audio enabled for ambience and effects; if it is missing, say so and record the model actually used. Use portrait, one output and the matching shot image in **Start frame**. For a continuation at the same angle, prefer the previous clip's actual cut frame. For a new angle use the new start image with the correct state. In the current workflow the user creates clips in Flow and puts them in `clips/`. If a Flow session is available and the user has authorized rendering there, use the correct settings and save results. For a shooting package, provide the folder link and where to put clips.
- Once clips arrive, measure duration with ffprobe and inspect real frames: a 1 fps strip per clip (`fps=1,scale=180:-1,tile=8x1`), then zoomed crops of the face, hands and feet at the moment the character reacts or reaches. Added eyebrows, eyelids, fingers and toes are the main failure; judge whether they read at phone size before failing a clip. Before regenerating a failed clip, find the prompt cause and rewrite it; in the first test, re-rolls that only fixed the lamp still produced fingers and eyebrows because the prompt still asked for a hand action.
- Then inspect real frames at action start, contact, reaction and transitions. Compare hands, eyelines, props and sound cues with adjacent shots. If action occurs earlier or later, adjust in/out and cues to the visible frame, and update actual source duration when appropriate. If a crucial action is missing, use an existing close-up/reaction or generate a supplemental image and clip. Keep natural pacing; avoid slowing entire clips or freezing frames to fill time. Recheck total frames and export the adjusted timeline before rendering.
- **Keep Flow picture and audio together.** Claude cannot listen: verify audio only by ffprobe/volumedetect (flag `max_volume` above about -1 dB as possible clipping) and report listening as `not_checked` unless the user confirms it. Check from frames that the mouth stays closed and that no speech appeared; if a clip speaks, regenerate it or mute it. Ask the user to audition ambience and effect timing across cuts. Record any unresolved audio issues.
- To render with Remotion, put the copy of `episode.jsx` in a project containing Remotion CLI 4.x, remotion and React. From that project run `npx remotion render episode.jsx Episode "$episode/final.mp4" --props="$episode/timeline.json" --public-dir="$episode"`, with `episode` as the absolute episode path. For the repository's available renderer, run `python3 <skill>/scripts/cut.py <episode>/cut.tsv --target <final-seconds> --render <episode>/final.mp4`. Both retain sound from the same picture cuts.
- Review the final film: Claude checks frame count, portrait frame, presence of an audio track and continuity at every cut from extracted frames, muted. The user watches it once at normal speed with sound for audio and cue timing. Report what was actually inspected, what is `not_checked`, and any remaining issues before delivering the film and caption.
